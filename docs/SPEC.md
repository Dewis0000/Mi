# Промт для создания сайта квест-комнат

> Скопируй весь текст ниже и отправь как задание на разработку сайта.

---

## Задача

Разработай полнофункциональный веб-сайт для сети квест-комнат (escape room) с системой онлайн-записи, личным кабинетом, программой лояльности, продажей видеозаписей прохождения и админ-панелью.

## Технологический стек

- **Frontend:** React + TypeScript, Vite, TailwindCSS, framer-motion для анимаций
- **Backend:** Node.js (NestJS или Express) + TypeScript, REST API
- **БД:** PostgreSQL + Prisma ORM
- **Авторизация:** JWT (access + refresh), подтверждение по номеру телефона
- **Хранилище:** S3-совместимое (видеозаписи с камер)
- **Видео:** HLS/RTSP-поток с IP-камер через медиасервер (например, MediaMTX или Nginx-RTMP)
- **Адаптивность:** обязательна — desktop, tablet, mobile

## 1. Главная страница

### 1.1. Шапка (фиксированная, sticky)

Одна горизонтальная линия, разделённая на три зоны:

- **Слева:** логотип + название сайта (кликабельно → возврат на главную)
- **По центру, со смещением вправо:** навигационные ссылки — «Квесты», «О нас», «Адрес», «Контакты». На мобильных — burger-меню
- **Справа:** кнопка профиля пользователя
  - если авторизован — аватар/иконка + имя, выпадающее меню (Профиль, Мои записи, Выход)
  - если не авторизован — кнопка «Зарегистрироваться»

### 1.2. Hero-блок

- Фоновая фотография (файл `фон`), размытие `blur(20%)` — примерно `backdrop-filter: blur(8px)` + тёмный оверлей для читаемости текста
- Слева — заголовок и описывающий текст (название сети, слоган, краткий питч)
- Под текстом — крупная CTA-кнопка **«Записаться»**
- Высота блока: 85–100vh

### 1.3. Блок «Активные квесты»

Карусель карточек квестов с адаптивной логикой отображения:

| Количество квестов | Поведение |
|---|---|
| **3 и более** | Горизонтальная карусель с прокруткой влево/вправо, стрелки + свайп на мобильных, точки-индикаторы |
| **Ровно 2** | Карточки центрируются по горизонтали, карусель отключена |
| **Ровно 1** | Карточка увеличивается в размерах, занимает расширенную ширину контейнера |

**Структура карточки квеста:**

- **Левая часть:** фотография квеста. Под фотографией — индикатор **уровня страха** (шкала, например 5 делений: «Лёгкий / Напряжённый / Страшный / Очень страшный / Экстрим»), визуально выделенный цветом
- **Правая часть:**
  - Название квеста
  - Краткое описание (2–3 строки)
  - Количество игроков: `от N до M`
  - Длительность: `N минут`
  - Возрастное ограничение: `N+`
  - Цена (от)
  - Кнопка **«Записаться»**

### 1.4. Блок «Информация»

Описание предоставляемых услуг: что входит в квест, дополнительные опции (фотосессия, аниматор, поздравление, подарочные сертификаты), правила посещения, FAQ-аккордеон.

### 1.5. Блок «Адрес и карта»

- Встроенная карта (Яндекс.Карты API или 2GIS)
- Клик по карте/адресу — переход на страницу маршрута в картах (внешняя ссылка, `target="_blank"`)
- Текстовый адрес, телефон, часы работы, ссылки на соцсети

### 1.6. Подвал

Логотип, навигация, контакты, политика конфиденциальности, обработка персональных данных.

## 2. Система регистрации и авторизации

### 2.1. Сценарий

1. Пользователь нажимает «Записаться», будучи неавторизованным → редирект на форму регистрации (или модальное окно) с сохранением намерения записи (после регистрации — возврат к выбранному квесту)
2. Ввод номера телефона в формате `+7 (___) ___-__-__`
3. Подтверждение номера одним из способов на выбор:
   - **Telegram** (бот отправляет код)
   - **ВКонтакте** (сообщение от сообщества)
   - **MAX**
4. Ввод кода подтверждения (6 цифр, таймер 60 сек, кнопка «Отправить повторно»)
5. Заполнение профиля: имя, дата рождения (опционально), e-mail (опционально)

### 2.2. Требования

- Повторный вход — только по номеру телефона + код (без пароля) либо по паролю, если пользователь его задал
- Rate limiting: не более 3 запросов кода в 10 минут на номер
- Согласие на обработку персональных данных — обязательный чекбокс (152-ФЗ)
- Защита от ботов: невидимая капча на форме отправки кода

## 3. Личный кабинет (профиль)

### 3.1. Разделы

**Активные записи**
- Карточки будущих квестов: название, дата, время, количество игроков, статус (ожидает подтверждения / подтверждена), итоговая цена с учётом скидки
- Кнопка отмены записи (с ограничением — не позднее чем за N часов)
- Кнопка «Перенести»

**История посещений**
- Прошедшие квесты с датами и результатом (прошли / не прошли, затраченное время)

**Система баллов (программа лояльности)**
- Текущий баланс баллов и текущий процент скидки
- За каждое посещение начисляются баллы; при накоплении порогов растёт скидка
  - Пример уровней: 0–99 → 0%, 100–299 → 5%, 300–599 → 10%, 600–999 → 15%, 1000+ → 20%
- **Сгорание баллов:** если пользователь не посещал квесты более N месяцев (например, 6), баллы начинают сгорать — по X% в месяц либо полностью. На странице отображается предупреждение с датой ближайшего списания
- История начислений и списаний

**Видеозаписи прохождения**
- Список прошедших квестов с возможностью **купить запись с камер**
- После оплаты — генерируется ссылка на скачивание файла (срок действия ссылки ограничен, например 30 дней)
- Отображается размер файла и длительность

**Онлайн-трансляция**
- Если квест пользователя сейчас идёт — доступна кнопка «Смотреть онлайн»
- Трансляция с камер в реальном времени (для друзей/родственников, ожидающих в холле или дома)
- Доступ только у владельца записи и приглашённых по временной ссылке
- Трансляция автоматически закрывается по окончании сеанса

### 3.2. Настройки

Изменение имени, номера телефона (с повторным подтверждением), привязанных мессенджеров, уведомлений.

## 4. Система записи на квест

### 4.1. Шаги формы

**Шаг 1 — Количество и возраст игроков**
- Ввод количества игроков
- Валидация: число должно укладываться в диапазон `min_players … max_players` конкретного квеста
- Указывается возраст каждого игрока либо диапазон «от минимального до максимального»
- Валидация возраста по ограничению квеста (например, 14+)

**Шаг 1a — Превышение лимита игроков**
- Если пользователь указывает количество больше максимального, система предлагает **аренду двух последовательных сеансов**: первая группа проходит квест, затем начинается второй сеанс с другими игроками
- При согласии лимит игроков снимается, бронируются два подряд идущих слота, цена пересчитывается

**Шаг 2 — Дата и время**
- Календарь: занятые даты визуально отмечены
- При выборе даты — список свободных временных слотов
- Слоты формируются с учётом длительности квеста + технического перерыва (уборка, перезарядка реквизита, например 15–30 минут)
- Занятые слоты недоступны; блокировка слота на 10 минут на время оформления заявки

**Шаг 3 — Подтверждение**
- Сводка: квест, дата, время, игроки, базовая цена, скидка по баллам, итог
- Поле комментария (день рождения, особые пожелания)
- Кнопка «Подтвердить запись»

### 4.2. После записи

- Уведомление в выбранный мессенджер с деталями
- Напоминание за 24 часа и за 2 часа до начала
- Статусы заявки: `новая` → `подтверждена` → `завершена` / `отменена` / `неявка`

## 5. Админ-панель

Доступна только пользователям с выданной ролью. Отдельный раздел `/admin`, скрытый от обычных пользователей.

### 5.1. Система ролей

- **Главный администратор** — полный доступ, единственный, кто назначает и переназначает роли
- **Заместитель администратора** — всё, кроме управления ролями
- **Бухгалтер** — доступ к финансовой отчётности и платежам
- **Оператор / администратор зала** — работа с заявками и записями

**Важно:** роли и пометки о них **не отображаются никому, кроме главного администратора**. Остальные сотрудники не видят, кто какую роль имеет, — в интерфейсе отображается только имя.

### 5.2. Функционал

**Заявки и записи**
- Таблица всех заявок: активные, подтверждённые, завершённые, отменённые
- Фильтры и поиск: по дате, диапазону дат, квесту, номеру телефона, имени, статусу
- Виджет «Ближайшая запись» — отображается на сайте/дашборде администратора: какой квест, во сколько, сколько игроков, контакт
- Календарное представление загрузки по дням и часам

**Работа с пользователями**
- Ручное подтверждение номера телефона, если у пользователя проблемы с автоподтверждением
- Регистрация пользователя вручную (приход без записи, запись по телефону)
- Просмотр и корректировка баланса баллов
- Блокировка пользователя (при систематических неявках)

**Редактирование записей**
- Изменение любых данных существующей записи: дата, время, квест, количество игроков, цена, скидка
- Добавление новой записи вручную
- Отметка «неявка», «завершено»

**Управление контентом**
- CRUD квестов: название, описание, фото, уровень страха, мин/макс игроков, длительность, возрастное ограничение, цена, расписание доступности, активен/скрыт
- Редактирование текстов главной страницы, адреса, контактов

**Видеозаписи**
- Автоматическая загрузка записей с IP-камер на сервер по окончании сеанса (привязка к записи по времени и номеру комнаты)
- Просмотр, выгрузка, удаление записей
- Ручная привязка записи к заявке, если автоматика не сработала
- Настройка срока хранения (например, 60 дней, затем автоудаление)

**Отчётность**
- Выручка за период, загрузка по квестам, средний чек, конверсия, количество неявок
- Экспорт в Excel/CSV

## 6. Дополнительные требования (добавлено сверх исходного ТЗ)

### 6.1. Безопасность
- Все роуты админ-панели защищены проверкой роли на бэкенде, а не только на фронте
- Логирование действий администраторов (кто, что и когда изменил)
- Хранение видеозаписей в приватном бакете, доступ только по подписанным временным ссылкам
- HTTPS обязательно, HttpOnly cookie для refresh-токена
- Валидация всех входящих данных на сервере (zod / class-validator)

### 6.2. UX
- Скелетоны и состояния загрузки для всех асинхронных блоков
- Понятные пустые состояния («У вас пока нет записей»)
- Все действия, меняющие данные, — с подтверждением
- Тёмная/светлая тема (тёмная по умолчанию — соответствует тематике квестов)
- Доступность: контрастность текста на размытом фоне не ниже WCAG AA, навигация с клавиатуры

### 6.3. Производительность и SEO
- Lazy-loading изображений, формат WebP/AVIF
- SSR или пререндер главной страницы для индексации
- Мета-теги, Open Graph, микроразметка `LocalBusiness` и `Event`
- `sitemap.xml`, `robots.txt`

### 6.4. Оплата
- Онлайн-предоплата или бронирование без оплаты (настраивается в админке)
- Интеграция с ЮKassa / Robokassa для покупки видеозаписей и предоплаты квестов
- Промокоды и подарочные сертификаты

### 6.5. Уведомления
- Шаблоны сообщений для Telegram / ВК / MAX
- Уведомления администраторам о новой заявке

## 7. Модель данных (минимальная)

```
User          — id, phone, phone_verified, name, birth_date, email,
                points, last_visit_at, role_id, blocked, created_at
Role          — id, name, permissions[]            // видна только главному админу
Quest         — id, title, description, photo_url, fear_level,
                min_players, max_players, duration_min, min_age,
                base_price, is_active
Schedule      — id, quest_id, weekday, time_from, time_to, break_min
Booking       — id, user_id, quest_id, date, time, players_count,
                ages, status, base_price, discount, final_price,
                comment, is_double_session, linked_booking_id
PointsLog     — id, user_id, delta, reason, created_at
Recording     — id, booking_id, file_key, duration, size,
                is_purchased, expires_at
AdminLog      — id, admin_id, action, entity, entity_id, created_at
```
