## Фаза 0. Аудит

### 0.1 Стек: расхождение с брифом

Бриф предполагает React + Vite + TypeScript + Tailwind и маршруты `/`, `/pricing`, `/docs`, 404.

В репозитории:

- Публичный сайт и кабинет — статический HTML, собранный из DC-артбордов `prototype/src/*.dc.html` скриптом `prototype/build.mjs` в `site/`. Скрипт использует только встроенные модули Node. Рантайм — свои файлы `dc-lite.js`, `theme.js`, `api.js`, `widgets-lib.js`, `widget-render.js`.
- React, Vite, TypeScript и Tailwind в сайте не используются.
- Единственный Vite-проект — игра «Выпендрёжник» в `vypendrezhnik/` (React и three.js). Она собирается отдельно и лежит в `site/vypendrezhnik/`.
- `design-system/` содержит `tokens.json`, `tokens.css` и `tailwind.config.ts`. Файл `tokens.css` копируется в `site/assets/`, но подключён только на странице токенов (`Code.dc.html`).
- Бэкенд — PHP (`server/app/lib/*.php`, точки входа в `server/public/`). База — SQLite или MySQL/MariaDB, версия схемы 15. Лимиты тарифов, голосование и подбор музыки считаются на сервере.

Варианты:

- **A. Редизайн в DC-артбордах (рекомендую).** Меняем разметку, стили и анимацию в `prototype/src`, сборка и бэкенд те же. Это совпадает с правилом брифа «меняется только разметка, стили и анимация». Минус: нет экосистемы React (Framer Motion, shadcn), анимации пишем на CSS и небольшом скрипте.
- **B. Новый фронт на React + Vite + TS + Tailwind** в отдельной папке (например, `site-next/`), сборка в тот же `site/`. Даёт стек из брифа, но либо дублирует кабинет, либо требует переписать его, что противоречит «логика не меняется».

### 1.2 Предмет и задача

- **Кто.** Стример на Twitch и его модераторы. Во время эфира у них нет времени читать сайт.
- **Задача сайта.** За минуту понять, что делает панель, и подключить канал.
- **Словарь предмета.** Лампа «в эфире», клавиша, фейдер, очередь, чат, алерт. Образы берём отсюда, а не из шаблонов SaaS.
- **Единственный объём.** Панель с клавишами, фейдерами и колесом. Это лицевая сторона пульта, который стример видит в студии. Всё остальное плоское.

### 1.8 Пять принципов (проверяемые)

1. **Один объём — панель.** Проверка: кроме панели нет теней, стекла и 3D.
2. **Цвет только лампой.** Проверка: в тексте и кнопках нет Эфира, Готово и Внимания.
3. **Пример вместо обещания.** Проверка: у каждого модуля строка из чата или очереди. Имена общие. Цифры только реальные: 60 с, 1000, 10, 100.
4. **Одна кнопка.** Проверка: на странице одна заливная кнопка, «Войти через Twitch».
5. **Движение по действию.** Проверка: лампы загораются один раз, когда панель появляется в кадре. Дальше — только по нажатию. При «меньше движения» горят сразу.

### 1.9 Самопроверка по брифу

- «Прибор, а не витрина» — выполнено: панель, лампы, рейка.
- Geologica везде, Martian Mono только для чисел — выполнено.
- Рейка 56 px, 12 колонок, максимум 1180 px, выравнивание слева — выполнено.
- Одна панель: пять клавиш, два фейдера, колесо — выполнено статично на холсте, 3D в Фазе 4.
- Запреты: стекло, градиенты, одинаковые карточки, дубли CTA, выдуманное — проверено по плану (см. 1.8). В коде не проверено.
- Hero не на весь экран: заголовок и панель занимают около 800 px.

### 1.10 Остаточные риски

- Светлый вариант может оказаться не тем, что имели в виду. Тогда — тёмный графит на тех же лампах (вопрос 1).
- Холст не рендерился: по правилам платформы проверку делаем по просьбе. Контраст посчитан, вёрстка не проверена глазами.
- Пример в чате — иллюстрация. Команды настоящие, имена общие, подписано «пример».
- Из FAQ, в коде не проверено: «без автосписаний» и «бот станет модератором канала». Проверим права бота при подключении.
- Geologica 500 на 61 px с кириллицей: читаемость проверим в Фазе 2–3.
