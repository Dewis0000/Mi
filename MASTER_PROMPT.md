## 2. Дизайн-требования

- Общий стиль: современный, чистый, "premium"-ощущение, много воздуха (whitespace), плавные анимации, аккуратная типографика. Избегай шаблонного "бутстрапового" вида.
- Тема: поддержка светлой и тёмной темы (переключатель + `prefers-color-scheme`).
- Палитра и шрифты: если не заданы явно в брифе — подбери сам гармоничную палитру (1 акцентный цвет + нейтральные) и связку шрифтов (например через Google Fonts / Fontsource): [ПАЛИТРА/ШРИФТЫ или "на твой вкус"].
- Адаптивность: мобильная версия обязательна, брейкпоинты минимум 375px / 768px / 1024px / 1440px, никакого горизонтального скролла.
- Анимации и интерактив: плавные transition/hover, скролл-анимации появления блоков, микро-интеракции на кнопках и карточках — без перегруза, только там, где это усиливает восприятие.
- Доступность (a11y): семантическая разметка, контраст текста, фокус-стили, alt-тексты, поддержка клавиатурной навигации.
- Изображения/иконки: используй иконки из lucide-react, для картинок — плейсхолдеры (Unsplash source URL или сгенерированные SVG-иллюстрации), которые легко заменить.

## 3. Технологический стек

Собери сайт на этом стеке (если для типа проекта из брифа что-то избыточно — упрости и явно об этом сообщи):

**Фреймворк и сборка**
- Next.js (App Router, TypeScript) — для сайтов с несколькими страницами/бэкендом.
  Для простого лендинга без бэкенда допустимо Vite + React + TypeScript.
- pnpm или npm для управления зависимостями.

**UI и стилизация**
- Tailwind CSS (последняя версия) как основа стилизации.
- shadcn/ui — компоненты (Button, Card, Dialog, Input, Tabs, Accordion, NavigationMenu, Sheet, Toast и т.д.), устанавливаемые через `npx shadcn@latest add ...`.
- Radix UI — как база для доступных примитивов (идёт вместе с shadcn/ui).
- `class-variance-authority`, `clsx`, `tailwind-merge` — для вариативных стилей компонентов.
- lucide-react — иконки.
- Ориентируйся на паттерны компонентов в духе каталогов 21st.dev / Aceternity UI / Magic UI (hero-секции, bento-грид, marquee, анимированные фоны, spotlight-карточки) — но пиши код сам, не копируй чужой проприетарный код дословно, а реализуй аналогичные по духу паттерны.

**Анимации**
- Framer Motion (`motion` / `framer-motion`) — переходы страниц, анимации появления, hover/tap эффекты, параллакс.
- Опционально GSAP — если нужны сложные scroll-triggered анимации.
- `tailwindcss-animate` — для простых keyframe-анимаций через классы.

**Формы и валидация**
- React Hook Form + Zod — все формы (контакты, регистрация, чекаут).

**Данные и состояние**
- TanStack Query (React Query) — работа с серверными данными/кэш.
- Zustand — простой клиентский стейт (если нужен, например корзина, UI-состояние).

**Бэкенд/данные (если бриф требует)**
- Next.js Route Handlers / Server Actions для API.
- Prisma + PostgreSQL (или SQLite для локальной разработки) как ORM, либо Supabase, если нужен готовый бэкенд с авторизацией и БД быстро.
- NextAuth.js (Auth.js) — если нужна авторизация.
- Resend или Nodemailer — отправка писем с форм.
- Stripe — если есть оплата/подписки.

**Контент**
- MDX (`next-mdx-remote` или Contentlayer) — если есть блог/статьи.

**Качество кода**
- TypeScript strict-mode.
- ESLint + Prettier с базовой конфигурацией.
- Простейшие smoke-тесты ключевых компонентов на Vitest + Testing Library (не перегружай тестами простой лендинг).

## 4. Структура и процесс работы

1. Сначала кратко опиши план: страницы, структуру папок, ключевые компоненты, схему данных (если есть бэкенд). Не проси разрешения продолжать — сразу переходи к реализации, если тебе не запретили явно.
2. Инициализируй проект нужным стековом (Next.js/Vite), поставь и настрой Tailwind, shadcn/ui, Framer Motion и остальные зависимости из раздела 3, релевантные проекту.
3. Создай переиспользуемую систему компонентов: Layout, Header/Navbar (с мобильным меню), Footer, Hero-секция, карточки/секции контента, формы, кнопки-варианты, тема (dark/light toggle).
4. Реализуй все страницы из брифа с реальным содержимым (не "lorem ipsum" на весь текст — пиши осмысленные тексты на нужном языке, соответствующие описанию продукта).
5. Добавь SEO-основы: метатеги, Open Graph, `sitemap.xml`, `robots.txt`, семантические заголовки.
6. Проверь, что проект собирается без ошибок (`npm run build` / `pnpm build`), исправь все ошибки типов и линта.
7. Запусти дев-сервер и, если у тебя есть возможность рендерить/скриншотить, визуально проверь основные страницы в светлой и тёмной теме, на десктопной и мобильной ширине; исправь визуальные баги.
8. Напиши короткий `README.md`: как установить зависимости, запустить локально, собрать и задеплоить (для выбранного хостинга), какие переменные окружения нужны (`.env.example`).
9. Сделай git-коммит(ы) с понятными сообщениями. Если тебя просили запушить в конкретную ветку/репозиторий — запушь; если нет — просто закоммить локально и скажи, что готово к пушу.
