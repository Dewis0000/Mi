# Развёртывание на хостинге reg.ru (ispmanager)

Хостинг: `server259.hosting.reg.ru`, пользователь панели `u3661097`, виртуальный хостинг (без root).

## Что важно знать заранее

- **API панели** — `https://server259.hosting.reg.ru/manager/ispmgr`. Официальный адрес на порту 1500 из облачной песочницы Claude недоступен (прокси рвёт соединение), а тот же API через `/manager/` на порту 443 работает.
- **Авторизация** — логин и пароль пользователя панели. Пароль не передаётся в чат: его кладут в переменные окружения среды Claude (`ISPMANAGER_USER=u3661097`, `ISPMANAGER_PASSWORD=…`). Новая сессия подхватывает их автоматически.
- **Полная версия сайта** (API + PostgreSQL) работает, только если в тарифе есть **Node.js-сайты** (ispmanager 6: обработчик «Node.js», версии 12–26, запуск `npm start` через pm2) и **PostgreSQL**. Проверка — командой `check` ниже.
- **Демо-версия** (`web/dist-demo/chernyhod.html`) — один статический файл, работает на любом хостинге. Но сервер в ней эмулируется в браузере: записи видит только сам посетитель. Годится для показа, не для работы с клиентами.

## Шаг 1. Проверить возможности тарифа

```bash
NODE_USE_ENV_PROXY=1 node deploy/ispmanager/ispmgr.mjs check
```

Команда выводит сайты (домены и папки), базы данных и варианты полей при создании сайта и базы. Смотрим, есть ли обработчик Node.js у сайта и тип `postgresql` у базы. Имена полей любой функции панели можно узнать так: `ispmgr.mjs form <функция>`.

## Шаг 2а. Полная версия (если есть Node.js и PostgreSQL)

1. Собрать пакет: `node deploy/build-bundle.mjs` → `deploy/out/chernyhod-site.zip`. Внутри сервер, миграции и собранный сайт; один процесс отдаёт и API, и страницы.
2. Создать базу PostgreSQL (функция `db.edit`, `sok=ok`; поля — из `form db.edit`).
3. Создать сайт (или изменить существующий): обработчик **Node.js**, версия **22 или новее**, подключение через порт или сокет (сервер поддерживает оба варианта: `PORT`/`INSTANCE_HOST` и `SOCKET`).
4. Загрузить архив в папку сайта (`/var/www/u3661097/data/www/<домен>`) и распаковать. Сделать это можно через менеджер файлов панели или функциями `file.upload` и распаковки архива (точные параметры — через `form`).
5. Положить `chernyhod.env` на два уровня выше папки сайта: `/var/www/u3661097/data/chernyhod.env`. Шаблон — `chernyhod.env.example` в архиве. Файл лежит вне веб-корня, поэтому веб-сервер его не отдаст. Обязательные значения:
   - `DATABASE_URL`;
   - `APP_URL` и `API_URL` — адрес сайта;
   - три секрета: `JWT_ACCESS_SECRET`, `SIGNING_SECRET`, `INGEST_SECRET`;
   - данные владельца: `SEED_OWNER_PHONE` и `SEED_OWNER_PASSWORD` (не короче 10 символов).
6. Команда запуска проекта — `npm start`. Зависимости панель ставит сама из `package.json`, при этом `postinstall` запускает `prisma generate`. При первом старте `dist/start.js` применит миграции, создаст роли, квесты и главного администратора и запустит сайт.
7. Пока не подключены Telegram Gateway, ВКонтакте или MAX, коды подтверждения отправить некуда. Для теста `AUTH_SHOW_CODES=1` показывает код в форме входа. Перед запуском для клиентов эту настройку нужно убрать.

Без консоли на хостинге не получится запустить медиасервер для камер (MediaMTX). Трансляции и автозапись с камер потребуют отдельный VPS или медиасервер.

## Шаг 2б. Если Node.js или PostgreSQL нет

- **Быстро показать сайт:** `npm --prefix web run build:demo`, затем загрузить `web/dist-demo/chernyhod.html` в корень сайта под именем `index.html`. Файл самодостаточный, но артефактная обёртка в нём не нужна: для хостинга его нужно обернуть в `<!doctype html><html lang="ru"><head><meta charset="utf-8"><meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover"></head><body>…</body></html>`.
- **Для работы с клиентами:** VPS (на reg.ru или где угодно) по общей инструкции из корневого README (`docker compose`, nginx, `server/Dockerfile`). Другой путь — тариф хостинга с Node.js и PostgreSQL.
